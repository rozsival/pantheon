# AGENTS.md

This file provides guidance to AI assistants (Claude, Gemini, Copilot, OpenCode etc.) when working with code in this
repository.

## Project Overview

Pantheon is a minimal, configurable baseline for a headless Ubuntu Server: storage, essential packages, unattended
upgrades, Docker, Tailscale, SSH hardening, UFW and fail2ban, plus opt-in extras (Homebrew with bottom, Starship,
Ghostty terminfo). It is deliberately generic: workloads that run on top of it (for example the Panther Minor AI stack)
live in their own repositories and install what only they need.

## Stack

- **Host**: Ubuntu Server 26.04 LTS+
- **CLI**: `./bin/pantheon`, generated by Bashly from `cli/`
- **Distribution**: release archive `pantheon.tar.gz` + `release/install.sh`; `pantheon update` for later versions

## Critical Rules

1. **Scope** — generic baseline only. Nothing specific to one workload (GPU drivers, an application's packages).
2. **Configurable defaults** — every value has a flag and an env var; a re-run keeps the operator's values (e.g. `ufw`
   adds rules instead of resetting, the timezone defaults to the current one). Anything destructive is opt-in
   (`ufw --reset`) or backed up (`setup ssh` moves `sshd_config.d` drop-ins to a timestamped directory).
3. **Code style** — Prettier (shell included, via `prettier-plugin-sh`) and ShellCheck (`pnpm run check` or
   `pnpm run fix`).
4. **Package manager** — `apt-get` only in scripts (never `apt`); `apt-get upgrade --with-new-pkgs` where
   `apt upgrade` was meant.
5. **Commits** — Conventional Commits v1.0.0, lowercase, no final punctuation, 100 chars max.
6. **Never edit or read `bin/pantheon`** — it is generated; edit `cli/` and run `pnpm run build:cli`.

## Key Files

- `README.md` — overview, quick start, the map of what runs on the author's server
- `docs/README.md` — documentation index and conventions; one domain per file in `docs/`
- `docs/installation.md` — prerequisites, installer, setup steps and extras, host Tailscale
- `docs/security.md` — SSH hardening, UFW (and why Docker ports bypass it), fail2ban
- `docs/cli.md` — command reference and maintainer workflow (strictly follow it for CLI changes)
- `cli/bashly.yml` — CLI schema; `cli/commands/setup/*.sh` — one file per setup step; `cli/lib/*.sh` — shared helpers
- `release/package.sh` — the runtime file set an install ships; add runtime files here

## Planning

When requested to plan a new feature or change, provide a clear outline that can be reviewed and approved before
implementation. It should also be a complete guide to any agent taking over the work and implementing it. Go straight
to the point, and avoid unnecessary verbosity. Each plan is written in a separate file in the `.agents/plans`
directory, with a name constructed as `YYYY-MM-DD-<short-description>.md`.
